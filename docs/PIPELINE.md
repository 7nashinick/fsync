# Fsync usage pipeline

The contract for the plugin. Code follows this document; where behaviour
and this document disagree, the behaviour is the bug.

One rule governs every flow: **one dialog, zero popups, nothing to
configure.** Anything the LiveSync + Setup URI journey asks of a user
that this document does not list is a defect Fsync exists to remove.

---

## 1. Definitions

| Term | Meaning |
|---|---|
| Server | An Fsync deployment: account panel + CouchDB. Reference: notes.foldoy.com / sync.foldoy.com |
| Account | Username + password, created by the server admin. One account, many vaults |
| Vault | One synced note collection. Server-side: one CouchDB database `v_<owner>_<name>`. Default name `main` |
| Vault ref | `main` for your own vault, `owner/main` for one shared with you |
| Passphrase | The end-to-end encryption key for one vault. Generated by the plugin, shown once, never stored server-side, never recoverable |
| Engine | The forked Self-hosted LiveSync core (MIT) embedded in Fsync. Users never see this word |
| Panel API | HTTPS endpoints on the server the plugin calls with Basic auth |

## 2. Surfaces

1. **The connect dialog.** The only window the plugin ever opens on its own.
2. **The settings tab.** Status and account info. Visited voluntarily.
3. **The status indicator.** A dot/icon in the status bar: syncing, idle, offline, blocked, error.
4. **The panel** (website). Accounts, sync codes for the legacy path, sharing, quotas, web viewer. The plugin links to it, never duplicates it.

## 3. The connect dialog, fully specified

Fields, top to bottom:

| Field | Shown | Rules |
|---|---|---|
| Username | always | lowercase, `[a-z][a-z0-9_-]{1,30}`, trimmed |
| Password | always | never persisted outside engine config |
| Passphrase | only when joining a vault that already has data | min 8 chars; label says whose passphrase it is |
| Advanced (fold, closed by default) | always | contains Server URL (prefilled) and Vault (prefilled `main`, accepts `owner/name`) |
| Connect button | always | disabled while a request is in flight; label changes to "Connecting" |

Dialog behaviour:

- Opens automatically on first run when the plugin is unconfigured. Never
  opens automatically again after a successful connect or an explicit close
  (closing is remembered).
- Reachable any time via command palette ("Fsync: Connect") and the
  settings tab.
- Every failure is shown inside the dialog, inline, in plain words.
  The dialog never closes on failure.

Error copy, exact:

| Condition | Message |
|---|---|
| Bad credentials | Wrong username or password. |
| No such shared vault / no access | No vault called `owner/name` is shared with you. |
| Server unreachable | Can't reach the server. Check your connection and try again. |
| Wrong passphrase (join) | Wrong passphrase for this vault. |
| Quota full (first upload) | This account is out of space. Free some on the panel, then retry. |

## 4. Flow: first device

Preconditions: account exists; this Obsidian vault holds the user's notes;
the server vault is empty or absent.

User does:
1. Install **Fsync** from Community plugins, enable it.
2. Dialog appears. Username, password. Connect.

Plugin does, with no further questions:
1. Verifies credentials against the panel API; resolves vault `main`
   (creates the server database if absent).
2. Detects the remote is empty → this is an INIT.
3. Generates a strong passphrase. Turns E2EE on.
4. Writes engine config in code: live sync on; size warnings, optional
   features, version notices off; recommended chunking.
5. Uploads this vault to the server.
6. Shows one reveal: the passphrase, once, with "save this, every device
   needs it, it cannot be recovered."

Target: under two minutes, one dialog, one reveal, zero questions.

## 5. Flow: another device (same account)

Preconditions: account exists; the server vault already holds notes; this
Obsidian vault is empty.

User does:
1. Install Fsync, enable it.
2. Dialog: username, password, passphrase (the field is present because the
   server vault has data). Connect.

Plugin does:
1. Verifies credentials; resolves vault `main`.
2. Detects the remote has data → this is a JOIN. Never offered a
   "set up new server" choice.
3. Writes the same in-code config, using the supplied passphrase.
4. Fetches the vault down. Live sync from then on.

If BOTH sides have data, and only then, one guarded question is allowed,
in these words: keep the server's copy, or keep this device's copy.

## 6. Flow: a vault shared with you

Owner (on the panel): shares the vault with a username, tells the joiner
the passphrase personally.

Joiner: the connect dialog, Advanced opened, Vault set to `owner/name`
(or the panel hands them an `obsidian://fsync?...` link that prefills it).
Otherwise identical to flow 5 (always a JOIN).

## 7. Steady state

- Typing syncs live. No buttons, no timers, no "replicate now".
- Settings tab shows: connected account, vault ref, live status, and
  storage used against quota (from the panel API). Nothing else.
- Quota exceeded: the server blocks writes; the plugin surfaces the
  server's message verbatim with a link to the panel. Deletions still sync.

## 8. Recovery

- Lost password: admin resets it on the panel; the plugin asks for the new
  password on next failure, nothing else changes.
- Lost passphrase: unrecoverable by design. The message says so and offers
  the only honest path: disconnect, keep local files, start a fresh vault.
- Server unreachable: work offline, sync resumes on return. Transient
  failures never raise popups; the status indicator carries the state.

## 9. Failure modes that must stay impossible

Each learned from live testing of the LiveSync journey.

| Failure | Old cause | Fsync rule |
|---|---|---|
| Typing never syncs | wizard set mode "On events", no events on | live mode written in code, never imported from a preset |
| Restart needed to sync | replication only opened at startup | open replication immediately after connect |
| Wrong branch wipes server | "new server" offered to a joining device | INIT vs JOIN chosen by data detection, never by the user |
| Popup fatigue | version notes, size warnings, optional features | all answered or suppressed in code |
| Passphrase lost silently | shown mid-wizard among noise | its own reveal step, nothing else on screen |

## 10. Build plan

1. Fork the engine (MIT) into this repo; build unchanged first.
2. Replace the unconfigured-startup seam with the Fsync connect dialog.
3. Bake flow 4/5 config writes and the INIT/JOIN data detection.
4. Panel API client: resolve vault, read quota.
5. Suppress or answer every dialog in section 9.
6. Rebrand: manifest `fsync`, settings tab, strings, the id-derived refs.
7. Community directory submission (server URL editable, so it serves any
   Fsync host, not only foldoy.com).
